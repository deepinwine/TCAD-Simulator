# 步骤眼睛：仅控制显示

用户于 2026-10-09 明确批准：眼睛不触发工艺重建。本规格取代
2026-10-08 实体剖面与逐步隐藏预览规格中的眼睛部分，实体剖面部分保持有效。

## 操作契约

- 点击眼睛只更新客户端可见性，不调用 run、set_step、import 或隔离重放。
- 正式网格、配方 enabled、执行状态、历史、保存文件均不改变。
- 同一种材料的不同沉积步骤必须能分别隐藏，不能用 material ID 代替步骤身份。
- 刻蚀、去胶、CMP 等没有独立显示实体时禁用眼睛并解释原因；不恢复已删除材料。
- 项目初始化不作为普通步骤显示；旧数据无法可靠归属时明确标记不支持，不能猜测。
- 中文/英文提示、独立按钮、键盘访问和 aria-pressed 都须覆盖。

## 已确认的数据缺口

`geometry_scene/scene.py` 当前按材料聚合 `MaterialMesh`，没有步骤来源。
因此不能仅在前端添加按钮就宣称逐步骤隐藏已实现。

拟在正常结构构建时记录显示来源，复用已有执行和事务边界；为可显示步骤提供
独立且稳定的显示对象。正常构建、首次生成显示数据可能增加内存和网格生成成本，
但点击眼睛不能执行工艺。来源必须随 snapshot/restore、失败回滚和网格变更同步。
后续减材删除的体素不能因显示来源数据而重新出现。

显示数据必须包含相邻同材步骤的内部边界，否则隐藏外层后内层仍可能缺面。
剖面也需对应步骤来源，不能只隐藏 3D 网格而保留该步骤的切面颜色。
Three.js 只渲染后端提供的数据，不在客户端计算工艺几何。

## 实施顺序与验收

1. 修复当前 Base64 大合法切片校验异常，复审通过。
2. 测试并实现后端显示来源与 snapshot 兼容，再添加只读显示数据接口；旧接口保持有效。
3. 接入步骤按钮、网格与剖面可见性；切换不重挂 Viewer、不重置相机。
4. 实测同材两次沉积分别隐藏、后续刻蚀结果保留、恢复显示、组合剖面一致。
5. 断言眼睛操作前后正式状态一致，且无执行请求；全量回归和两阶段审查后交付。

不实现之前提议的 `/api/structure/visibility_preview` 或 preview token 重建路径。
